# Pull Request 白盒门禁清单 (PR Whitebox Gate)

> 本门禁是合并代码前的必要核验清单，确保所有合入主干的代码符合白盒可推演、可定位与因果可追溯契约。  
> 任何标记为【通过】的条目必须具备代码中的事实证据（包含文件路径与行号）。

---

## 门禁一：需求完整性与行为一致性 (基线门禁)

- [ ] **需求完整覆盖**：本次变更 100% 满足规格说明中定义的业务逻辑与边缘用例，未以“简化代码/消除复杂度”为由裁剪已确认的业务分支。
- [ ] **正反例行为等价**：重构的代码在所有成功与边缘失败场景下的对外输出、返回值和副作用与重构前保持严格一致。

---

## 门禁二：失败处理与因果保留 (P0 核心门禁)

- [ ] **无静默吞错 (W01)**：代码中不存在空的 `catch` 块；所有捕获的异常要么在边界被记录处置，要么被重新抛出；不存在无因果的 `return null/false` 逃避错误。
- [ ] **因果链完整保留 (W07)**：所有重新抛出或包装的高层业务异常均通过 `{ cause: err }` 或 `raise ... from err` 传递底层原始错误。
- [ ] **外部校验 vs 内部不变式 (W06)**：在系统 I/O 边界完成模式收窄；内部不变式破坏时使用断言快速失败 (Fail Fast)，不存在伪防御性 `?.` 和 `?? ""` 掩盖损坏 (W10)。

---

## 门禁三：状态建模与不可变性 (P0 / P1 门禁)

- [ ] **无未声明共享修改 (W02)**：所有函数均未直接对外部传入的对象或数组进行原地属性篡改（in-place mutation）；写操作必须返回新分配的浅拷贝或在命名上显式声明。
- [ ] **排他性状态建模 (W05)**：涉及异步生命周期、流程状态的场景，禁止使用 3 个以上布尔值组合；必须采用判别联合 (Discriminated Union) 或显式状态机表达合法状态。
- [ ] **函数命名与副作用匹配 (W09)**：以 `get`、`is`、`find`、`calculate` 等查询命名的函数完全是纯计算，不含写状态、网络写请求或缓存变更。

---

## 门禁四：可推演性与认知工效 (P1 门禁)

- [ ] **控制流扁平化 (W04)**：核心业务逻辑采用卫语句提早返回 (Early Return)；嵌套深度超过 3 层的代码段已进行审阅评估，不存在无必要的深层 if 嵌套。
- [ ] **无无边界幽灵抽象 (W03)**：不存在既无契约防腐、又无单测隔离价值的纯单行透传包装函数。
- [ ] **行为就近编排 (W08)**：特定功能私有的逻辑与数据结构依据实际职责与稳定边界就近定义在特性目录内，未随意倾倒至全局通用目录。

---

## 门禁五：日志安全与合规 (P0 核心门禁与 P2 规范)

- [ ] **严禁敏感凭据泄露 (W11 - P0 核心门禁)**：日志、异常堆栈与前端返回中严禁明文出现密码、Token、Bearer 鉴权头、私钥或 PII 隐私数据；敏感字段必须脱敏或排除。
- [ ] **边界单点日志 (W07 - P1 门禁)**：错误日志仅在请求入口、工作流 Worker 根节点等承担处置责任的边界记录 1 次 ERROR；中间业务层未重复打印造成日志洪泛。
- [ ] **链路标识关联 (W12 - P2 门禁)**：每条业务与错误日志均附带链路追踪标识 (`traceId` / `requestId`) 以及定位所需的最小必要业务主键。
- [ ] **消除魔数与魔术字符串 (W13 - P2 门禁)**：分支判断中无未解释的硬编码常数，已统一提取为具名常量或领域枚举。
